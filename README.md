# 贴吧（第三方客户端）

> 免责声明：本项目非官方、非商业、仅供个人学习与开源交流，与百度无关。
> 百度没有公开 API，接口来自对官方客户端/网页的分析，随时可能变更或失效；
> 账号可能被风控限制。不要用本项目做商业化、批量/高频请求、绕过会员或广告。
> 应用显示名仍为“贴吧”时存在商标误导风险，正式发布前建议改名并去掉百度/贴吧 Logo。

iOS 17、SwiftUI、无第三方依赖、XcodeGen 构建的独立贴吧客户端。
只做四件事：扫码登录、阅读、发帖、回复。不做直播、视频、商城、会员等。

## 结构（三层，接口变动只改适配层）

- UI 层：`HomeView`、`ThreadListView`、`ThreadDetailView`、`ComposeView`、`LoginView` 等，只用自有模型。
- 数据模型层：`Models.swift`（Forum、Thread、Post、SubPost、User/AuthorInfo），UI 不直接使用接口原始字段。
- 接口适配层：`TiebaAPI.swift`（`TiebaClient`），所有请求、参数拼装、签名、解析只在这里。
- 安全红线：登录只用 WKWebView 官方登录页，凭证只存本机 Keychain，不自建密码框、不上传服务器、不打日志；
  不伪造设备指纹（已删除上一版的本机 UUID cuid）；验证码一律交给用户手动处理，不自动识别或绕过；
  发帖/回复提交间隔不少于 5 秒，连续点击不会连发；列表、详情按页短时缓存 60 秒，减少重复请求。

## 功能

- 扫码登录：原生二维码 + 网页扫码（百度官方二维码，主入口之一）
- 阅读：吧列表（本地保存）、帖子列表分页、楼层列表分页、楼中楼分页、只看楼主（本地过滤）
- 帖子排序：帖子列表顶部三个分页——热门（回复数降序）、回复时间（最后回复时间降序）、新帖（发帖时间降序）；排序只针对已加载的帖子，翻页后重新排
- 首页：登录后显示“我关注的吧”（客户端关注接口，拉不到时退回本地吧），顶部“排序”按钮开/关拖动排序，顺序本地保存；“我的吧”同样可拖动排序
- 帖子详情：顶部显示楼主用户名、吧名、回复数；报错里不再显示 tid；客户端接口全部报删帖时自动改走网页版帖子页抓楼层文字和作者名（只做文字，第 1 页）
- 列表界面仿 NodeSeek 截图：顶部新帖子按钮 + 吧名 + 加号发帖、横向排序标签（选中橙色下划线）、每行头像首字 + 标题 + 作者·相对时间·吧名 + 右侧浏览/回复数（10000 以上用 k）
- 头像：user_list 的 portrait 走 https://tb.himg.baidu.com/sys/portrait/item/<portrait>，加载失败或为空时退回首字圆头像
- 关注的吧：客户端接口为空时改走网页版“我的吧”页面，从 /f?kw= 链接里取吧名
- 帖子详情：原生接口（含 POST 再试）拿不到楼层时，详情页有“用网页版打开这条帖子”按钮和右上角“网页版”，直接用官方帖子页看楼层、作者、头像（与网页扫码共用 Cookie）
- 发帖：发主题（标题 + 内容）
- 回帖：帖子底部回帖、每楼的楼中楼回复
- 未登录也能阅读；发帖、回复按钮在未登录时提示先登录
- 所有网络错误、服务端错误都在界面上以中文显示，不静默失败

## 登录说明

- 原生扫码：App 向百度 passport 请求二维码，展示后用百度 App / 贴吧 App 扫码并确认，App 每 2 秒轮询一次，最多 120 次（约 4 分钟），轮询返回里一旦出现 BDUSS 即完成登录。2026-10-27 真机反馈“返回数据无法解析”后已改：先预取 passport 首页 Cookie，UA/Referer 按浏览器发，按 tpl=pp、tpl=tb、qrlogin=1 三组参数依次尝试，img/sign 在整份 JSON 里递归找，失败时把服务端原返回前 200 字显示出来，不再只给一句笼统报错。
- 网页扫码：登录页上的「网页扫码（百度官方二维码）」，打开百度 passport 登录页（该页本身有扫码），App 每 2 秒检查一次网页 Cookie，拿到 BDUSS 即完成登录。原生扫码接口格式一变就走这里，它不依赖接口返回格式。
- BDUSS / STOKEN 只保存在本机 iOS Keychain，不写 UserDefaults、不打日志、不经过任何自有服务器。所有贴吧请求都直连 `c.tieba.baidu.com`（发帖凭证走 `tieba.baidu.com/dc/common/tbs`）。
- 退出登录：首页右上角「退出登录」，即删除 Keychain 里的 BDUSS 和 STOKEN。

## 构建

```sh
xcodegen generate
xcodebuild -project Tieba.xcodeproj -scheme Tieba -sdk iphoneos \
  -configuration Release CODE_SIGNING_ALLOWED=NO build
```

也可以用 `.github/workflows/build-ipa.yml`：推送到 main 分支后在 macOS runner 上生成未签名 IPA，产物 `Tieba-unsigned.ipa` 会发布到 `builds` 分支（附 `ipa.sha256`、`ipa_part_*` 分片和 `ipa_parts.count`），侧载安装。

## 已知未真机验证点

以下均未在本机验证（本机无 Xcode、无真机），按可能性排序，真机联调时先查这几处：

1. **原生扫码**：`passport.baidu.com/v2/api/getqrcode` 的返回格式和 `channel/unicast?channel_id=<sign>` 轮询返回里是否真的直接带有 BDUSS（JSON 或 Set-Cookie）。2026-10-27 真机已报一次“返回数据无法解析”，修复后失败会显示服务端原返回前 200 字，凭那段文字才能确定是参数、Cookie 还是字段名的问题。如果原生扫码仍失败，直接用「网页扫码（百度官方二维码）」登录——它直接读网页 Cookie，不依赖接口返回格式。
2. **帖子详情必须登录后看（2026-10-27 实测）**：匿名请求 `c/f/pb/page` 对两条帖子（含吧公告帖）都返回 350004“帖子可能已被删除”，不是帖子真的被删；不带 sign 则返回 110001。详情页未登录时会先提示这一点。已登录后详情仍报 350004 的话，把详情页显示的 tid 发回来再查（可能还缺服务端要的设备/鉴权字段）。
3. **作者名靠 user_list 映射（2026-10-27 实测）**：`frs` 的 thread 条目里 author 对象只有 show_icon_list、没有用户名，用户名在顶层 user_list 里按 author_id 映射，字段是 name_show（name 也可能同值）。代码已按此映射，楼层/楼中楼同理。
4. **发帖签名与 tbs**：`c/c/thread/add`、`c/c/post/add`、`c/c/comment/add` 的签名算法（参数按 key 排序拼 `key=value` 后加 `tiebaclient!!!` 再 MD5）与 `dc/common/tbs` 返回的 tbs 是否仍被当前服务端接受。签名或 tbs 一变，发帖会直接报服务端原错，界面会原样显示。
5. **帖子/楼层字段名**：`c/f/frs/page`、`c/f/pb/page`、`c/f/pb/floor` 的 `thread_list`、`post_list`、`subpost_list` 结构与作者、时间、内容片段（type 0 文字、type 3 图片 `origin_src`）字段是否与代码假设一致。解析已做防御处理（缺失字段用默认值，不崩溃），但字段名一旦改名，列表可能出现空白或缺内容。pb 的 post 字段尚未实测到（匿名请求拿不到 post_list），登录后若楼层仍空白，按详情页 tid 再查。
6. **风控**：新号、高频发帖、敏感词可能触发验证码、删帖或封号。发帖失败时界面显示的是服务端原错，按原错处理，不要反复重试。
7. **只看楼主**：优先按作者 id 过滤，id 为空时退回按作者名；若服务端返回的作者名格式不一致（如昵称与用户名混用），过滤可能漏楼层。
